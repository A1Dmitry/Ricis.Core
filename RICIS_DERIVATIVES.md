# Формальная производная RICIS

## Принцип

`DxDt()` строит производную как **символьную перестройку expression tree**. Он не вычисляет классический предел, не применяет правило Лопиталя, не использует численную разность и не аппроксимирует наклон. Если в построенном дереве возникает сингулярность, её обрабатывает существующий конвейер RICIS: L1, SP2, O(1), A1, A4–A7.

> Производная в этой реализации — самостоятельное производное дерево. Исходная лямбда не изменяется.

## Generic API

```csharp
using System.Linq.Expressions;
using System.Numerics;
using Ricis.Core.Extensions;

Expression<Func<BigInteger, BigInteger>> f = t => t * t * t;
Expression<Func<BigInteger, BigInteger>> dxDt = f.DxDt();

// Псевдоним с тем же контрактом.
Expression<Func<BigInteger, BigInteger>> alsoDxDt = f.Derivative();
```

Оба extension-метода имеют ограничение `where T : INumber<T>` и создают типизированные `T.Zero` и `T.One`; они не приводят произвольные finite-выражения к `double`.

| Входной узел | Символьная перестройка |
|---|---|
| Константа `C` | `0` |
| Тот же параметр времени `t` | `1` |
| Другой параметр | `0` |
| `F + G`, `F − G`, `−F` | линейная перестройка производных |
| `F · G` | `dF·G + F·dG` |
| `F / G` | `(G·dF − F·dG) / G²` |
| `F^n`, где `n` — целая постоянная | `n·F^(n−1)·dF` |

Перед построением производной исходная лямбда проходит L1/SP2. Поэтому `d(t/t)/dt` начинается с `d(1)/dt` и даёт `0`; оно не строит классическую форму частного `0/0`.

## Double-функции

Для `Expression<Func<double,double>>` добавлены правила цепочки для `Math.Sin`, `Math.Cos`, `Math.Tan`, `Math.Exp`, `Math.Log`, `Math.Log10`, `Math.Sqrt`, `Math.Sinh`, `Math.Cosh`, `Math.Tanh` и `Math.Pow(F, n)` с постоянной `double`-степенью. Эти правила также создают выражения символически.

## Неизвестные операции

Неподдержанный узел не подменяется нулём. Он сохраняется как extension-узел `D_t(F)`, где `t` — исходный параметр времени. Это удерживает информацию для дальнейших структурных операций RICIS и исключает ложное утверждение о постоянстве функции.

## Generic и полюса

Сертифицированный поиск вещественных ключей пока относится к домену `double`. Для finite-лямбд другого `INumber<T>` сохраняются L1, структурный SP2 и прямые O(1)-формы; библиотека не пытается привести такой `T` к `double` только ради поиска корней знаменателя.

## Регрессии

Набор `RicisDerivativeSuite` фиксирует D01–D09: `int`, `decimal`, `BigInteger`, L1 перед производной, отложенную неизвестную функцию, псевдоним API, `Expression.Power`, `Math.Sin` и `Math.Pow`.
