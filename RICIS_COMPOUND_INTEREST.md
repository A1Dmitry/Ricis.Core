# Сложный процент как expression-операция RICIS

## Формула

`CompoundInterest` строит отложенное expression tree для формулы:

> `P = S · (1 + r / 100)^n`,
>
> где `S` — principal, `r` — ставка в процентах за период, `n` — число периодов.

Операция создаёт **формулу**, а не прогноз, совет, оценку доходности или финансовую рекомендацию. Она не вызывает входные делегаты, не использует пределы или правило Лопиталя и не подставляет значения скрытно.

| Перегрузка | Контракт |
|---|---|
| `S.CompoundInterest(r, int n)` | `S` и `r` — отложенные scalar-лямбды, `n≥0` — точное целое число периодов; степень разворачивается в typed-произведения |
| `S.CompoundInterest(rate, int n)` | `rate` — типизированная константа, построенная как constant expression |
| `S.CompoundInterest(r, n)` для `double` | Все три аргумента — отложенные лямбды; сохраняется явный узел `Math.Pow(1+r/100,n)` |

## Точность и нормализация

Для generic-формы `T : INumber<T>` используется `T.CreateChecked(100)`, `T.One` и повторное `Expression.Multiply`; поэтому выражение не приводится к `double`. Это важно, в частности, для `decimal` и `BigInteger`.

`S` и `r` сначала проходят обычный RICIS-конвейер L1 → SP2 → O(1) → A1/A4 → A5–A7, затем связываются с общим параметром и формируют независимое результирующее дерево. Например, ставка `x/x` нормализуется в типизированную единицу до построения `1+r/100`.

Для exact generic-периодов отрицательный `n` запрещён и вызывает `ArgumentOutOfRangeException`. В double-перегрузке знак и значение отложенного `n` не вычисляются при построении: они остаются частью явного `Math.Pow`-узла и следуют обычной классической семантике при исполнении результата.

## Консоль и регрессии

```bash
dotnet run --project Ricis.Console/Ricis.Console.csproj -c Release -- --interest-demo
```

Регрессии `INT01`–`INT07` фиксируют decimal-формулу, привязку отложенных `S` и `r`, правило `n=0`, точность `BigInteger`, dynamic `Math.Pow`, отклонение отрицательных целых периодов и нормализацию L1.
