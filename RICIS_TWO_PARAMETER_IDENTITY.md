# RICIS Previous-Parameter Identity

## Нормативная постановка

Рассматривается одна отложенная функция `F`, текущий параметр `x` и строго определённый второй параметр `x−1`. Независимый параметр `y` в постановку не вводится.

Проверяемая предпосылка имеет вид:

```text
F(x) = F(x−1)
```

После сертификации этой предпосылки RICIS строит отношение:

```text
(F(x) / F(x−1)) - 1 = 0
```

Строгая RICIS-цепочка:

```text
F(x) = F(x−1)
→ F(x)/F(x−1) = F/F
→ F/F = 1                  [L1 identity, приоритет RICIS]
→ 1 - 1 = 0                [алгебраическое тождество]
```

Если оба ответа являются нулевыми payload, классическое `0/0` не используется как основание вывода. RICIS сохраняет индексы и применяет свой bridge `0_F/0_F → 1`, после чего выполняется тот же шаг `1−1→0`.

## Разделение ответственности

`RicisPreviousParameterIdentityProofCase` принимает delayed expression `F(u)`, создаёт `F(x)` и `F(x−1)` через parameter rebinding, прогоняет оба выражения через RICIS pipeline, проверяет structural equality и формирует ratio-minus-one. В monitor отдельно фиксируются `PARAMETERS`, `IDENTITY` и `RATIO`.

Внутри proof case нет классического вывода о периодичности. Результат принимается только после того, как два конкретных структурных ответа `F(x)` и `F(x−1)` совпали согласно L1 identity и текущим RICIS transformation rules.

## Regression coverage

| Case | Нормативный результат |

| `PREV01`: `F(u)=7` | `F(x)=F(x−1)`; `(F(x)/F(x−1))-1 → 0` |
| `PREV02`: `F(u)=0` | RICIS `0_F/0_F→1`; затем `1−1→0` |
| `PREV03`: `F(u)=u` | `F(x)` и `F(x−1)` различны; identity proof блокируется |

`RicisPreviousParameterIdentitySuite` подключён сразу после первичного Axiom Gate.

## Граница утверждения

Доказан точечный RICIS implication: если ответы одной функции на параметрах `x` и `x−1` сертифицированно равны, то `(F(x)/F(x−1))-1` структурно сводится к нулю. В постановке нет параметра `y`, нет замены `x−1` на произвольную точку и нет обращения к классической периодичности.
