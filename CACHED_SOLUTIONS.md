# CachedSolutions

`CachedSolutions` — fallback-механизм для случая, когда внешний агент недоступен. Он использует только решения, зафиксированные в локальных регрессионных тестах, и поэтому рассматривает найденный ответ как **гипотезу**, а не как истину.

## Поток обработки

1. `CachedSolutionIndex.FindSimilar` строит структурную форму запроса и ищет похожие expression tree среди проверенных тестовых формул.
2. Ближайшее решение выдаётся как `ClassicalHypothesis` вместе с источником теста и коэффициентом сходства.
3. Запрос повторно проходит через переданный deep-RICIS reducer. В production-сценарии сюда должен передаваться полный RICIS III pipeline, а не только поверхностный visitor.
4. Результат сравнивается с сохранённым `RicisExpectation` через структурный comparer, включая индексированные сингулярности.
5. Только при точном совпадении `RicisValidated=true`. При расхождении ответ остаётся неподтверждённой гипотезой и не должен автоматически выдаваться пользователю как решение.

## Почему ожидания разделены

Классическая алгебра может сократить выражение, потеряв ограничения области определения. RICIS III обязан сохранять полюса, нули, индексы и отложенные части выражения. Поэтому каждая запись содержит два независимых результата: `ClassicalExpectation` и `RicisExpectation`.

## API

Основные типы находятся в `CachedSolutions/CachedSolutionModels.cs`:

- `CachedSolution` — формула, классическое ожидание, RICIS-ожидание и источник теста;
- `CachedSolutionIndex` — поиск и fallback-разбор;
- `CachedSolutionProposal` — гипотеза и результат её глубокой проверки;
- `DefaultCachedSolutions` — начальный каталог решений из существующих Reduce-регрессий.

Публичный метод `ResolveWithoutAgent` намеренно не скрывает неудачную проверку: он возвращает предложение с `RicisValidated=false`, если глубокая редукция не совпала с кешированным ожиданием.

## Startup и 3D map

`DefaultCachedSolutions.CreateIndex()` зарегистрирован в `Ricis.WebApi/Program.cs` как startup singleton. Поэтому подтверждённые записи доступны с первого запроса через `GET /api/cached-solutions/map-bubbles`.

Endpoint возвращает объект с полем `map` и массивом `bubbles`. Каждый bubble содержит `id`, `displayName`, `formula`, `classicalResult`, `ricisResult`, `sourceTest`, `sourceUrl`, `explanation`, `notes`, `status`, `tags` и координаты `x`, `y`, `z`. В endpoint попадают только записи со статусом `confirmed`; неподтверждённые гипотезы намеренно исключаются.

## Регрессии

Поведение покрыто в `UnitTests/CachedSolutionsFallbackTests.cs`: успешное подтверждение, отказ при конфликтующем глубоком результате и отсутствие гипотезы для несовместимой формы.
