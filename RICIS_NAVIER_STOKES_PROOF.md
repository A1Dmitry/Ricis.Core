# RICIS proof-сценарий Навье—Стокса

## Назначение и запуск

`Ricis.NavierStokes.Console` — самостоятельный .NET 8-проект, который строит и документирует символический proof-сценарий для выбранного гладкого поля. Запуск выполняется следующей командой:

```bash
dotnet run --project Ricis.NavierStokes.Console/Ricis.NavierStokes.Console.csproj -c Release -- --stationary-vortex
```

Консоль не компилирует и не численно вычисляет поля для получения proof-результата. Она передаёт отложенные `Expression<Func<double,double,double,double,double>>` в `ProveNavierStokesIdentity` и печатает сформированный `StringBuilder`-документ. Компиляция expression tree допустима только как отдельная классическая проекция конечного символического результата, например в регрессиях.

## Сертифицируемое поле

| Объект | Отложенная форма |
|---|---|
| Скорость | `u(x,y,z,t)=(-y,x,0)` |
| Давление | `p(x,y,z,t)=(x²+y²)/2` |
| Вязкость | `ν=1` |

Метод строит точные деревья для дивергенции, временной производной, конвективного переноса, градиента давления, лапласиана и остатка

\[
R=\partial_tu+(u\cdot\nabla)u+\nabla p-\nu\Delta u.
\]

Для данного поля proof-сертификат выдаётся только после структурного подтверждения `∇·u=0` и того, что каждая компонента `R` является обычным или индексированным нулём RICIS. Сертификат имеет статус **конечного символического выведения** для указанного поля; он не является численным решателем уравнений и не делает утверждений о произвольных решениях.

## Нормативная нулевая семантика

> `F·0 → 0_F` является обязательным O(1)-мостом во всех контекстах, включая промежуточные expression tree символьной производной. Локальный calculus-редуктор не вправе заменять это выражение на безымянную константу `0` до применения RICIS-конвейера.

Индекс `F` остаётся доступен последующим фазам, документному proof-слою и диагностическому `ToString()`. В частности, символическая производная может печатать компоненту как `0_{F}`. Такой узел обозначает точный нуль RICIS, поэтому участвует в правилах `Z-01`, `Z-02` и в структурном признании нулевого остатка.

Для совместимости с обычным .NET expression tree `ZeroInfinityExpression.Reduce()` строит typed native zero **только при вызове `.Compile()`**. Эта проекция не изменяет исходное символическое дерево, его индекс либо сертифицированные ключи.

| Код | Нормативное правило | Символический результат |
|---|---|---|
| `LIM-01` | O(1)-мост произведения | `F·0 → 0_F` |
| `Z-01` | Сумма indexed zero | `0_F+0_G → 0_{F+G}` |
| `Z-02` | Произведение indexed zero | `0_F·0_G → 0_{F·G}` |
| `LIM-03` | Конечное на indexed infinity | `F/∞_G → 0_F` с сохранением ключей `G` |
| `A6` | Геометрическое произведение | `0_F·∞_G → F·G` |

Правило `F/∞_G → 0_F` реализовано после передачи готовой indexed infinity через A1/A4 к фазе стандартных операций. Корни знаменательной бесконечности сохраняются как контекст узла `0_F`; индексом нуля остаётся исходный конечный числитель `F`.

## Нормативная цепочка NS-01–NS-07

| Шаг | Построение | Требование к proof |
|---|---|---|
| NS-01 | Типизированное поле `(-y,x,0)` | Три независимых deferred expression tree. |
| NS-02 | `∂xU+∂yV+∂zW` | Дивергенция является нулём RICIS. |
| NS-03 | `∂tu` | Временная производная строится символически; стационарные компоненты дают typed zero либо `0_F`. |
| NS-04 | `(u·∇)u` | Конвективный перенос строится без вызова делегата. |
| NS-05 | `∇p` | Градиент давления сохраняется как expression tree, включая zero-sector. |
| NS-06 | `Δu` | Лапласиан вычисляется покомпонентной перестройкой дерева. |
| NS-07 | `R=∂tu+(u·∇)u+∇p−νΔu` | Каждая компонента структурно является нулём RICIS; только тогда формируется сертификат. |

Отладочный вывод может содержать индексированные нули, например `0_{(x+-y)}` в промежуточной компоненте переноса или более составной индекс в нулевой компоненте градиента. Это не ошибка и не численная аппроксимация: индекс фиксирует происхождение нуля, которое раньше терялось при локальной finite-редукции.

## API proof-слоя

| API | Назначение |
|---|---|
| `RicisVectorField3` | Три независимые отложенные компоненты поля `U,V,W`. |
| `PartialDerivative` | Точная символьная частная производная по `X`, `Y`, `Z` или `T`. |
| `Gradient` | Пространственный градиент scalar-поля. |
| `Divergence` | Пространственная дивергенция векторного поля. |
| `Laplacian` | Покомпонентный пространственный лапласиан. |
| `TimeDerivative` | Покомпонентная производная по времени. |
| `ConvectiveDerivative` | Поле `(u·∇)v`. |
| `ProveNavierStokesIdentity` | Документирует NS-01–NS-07 и возвращает сертификат только для структурно нулевого остатка. |

## QA-реестр и регрессии

| ID | Найденный случай | Исправление | Регрессия |
|---|---|---|---|
| NS-QA-01 | `FiniteCalculusReductionVisitor` заменял `F·0` на обычный `0`, уничтожая индекс в производной. | Произведение с нулём передаётся O(1)-мосту; полученный `0_F` остаётся special node. | NS07 |
| NS-QA-02 | Неприводимый `0_F` нельзя было использовать в повторной подстановке параметров или .NET-компиляции. | Подстановка сохраняет special-узел; `Reduce()` предоставляет typed-zero проекцию только при `.Compile()`. | NS01, NS02, NS07 |
| NS-QA-03 | Выражения вида `0_F±G`, `0_F·G` и `0_F/G` не нормализовались, хотя индекс уже был зафиксирован. | Добавлены согласованные finite-следствия indexed-zero algebra без удаления индекса в момент его создания. | NS02, NS03 |
| NS-QA-04 | Готовая `∞_G` ошибочно попадала в анализ корней A1/A4 до стандартной фазы. | Деление на готовую indexed infinity направляется к правилу `F/∞_G→0_F`; ключи `G` сохраняются. | NS08 |
| NS-QA-05 | Общий simplifier формировал `Power(double,int)` при канонизации индекса. | Показатель `Pow` строится в scalar-типе основания. | NS02, NS03 |
| NS-QA-06 | Стационарная производная могла печатать артефакт `-0`. | Константный нуль канонизируется как положительный typed zero. | NS06 |

Полный регрессионный набор включает **NS01–NS08**. NS07 проверяет одновременно сохраняемое представление `0_F` и его конечную исполнимую проекцию; NS08 проверяет индекс `F`, ключи `G` и проекцию `F/∞_G` в `0_F`.

## Граница сценария

Сценарий остаётся строго символическим. Внутри RICIS не используются пределы, правило Лопиталя, численная дискретизация или подбор решения. Расширение класса сертифицируемых полей требует новых типовых правил и регрессий; уже выданный сертификат относится только к указанному expression-tree сценарию.
