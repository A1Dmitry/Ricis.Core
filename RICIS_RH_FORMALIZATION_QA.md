# QA: границы формализации Riemann-связанного proof-сценария

## Итог аудита

Текущее ядро **корректно** строит и проверяет конечное следствие `sigma=1/2` из переданных уравнений `sigma+mirrorSigma=1` и `sigma−mirrorSigma=0`. Оно не имеет формальных средств, чтобы установить, что эти уравнения следуют для всех нетривиальных нулей дзета-функции. Поэтому статус реализованного результата — **условная конечная теорема**, а не доказательство гипотезы Римана.

Успех полного регрессионного набора подтверждает отсутствие известных регрессий в покрытых ветвях реализации. Он не заменяет доказательство внешней предпосылки: тесты могут доказать соответствие программы её спецификации только в объёме самих тестов, но не истинность произвольной математической аксиомы, записанной текстом.

## Открытые уязвимости и вопросы для решения

| ID | Уровень | Уязвимость | Почему это существенно | Предложение для обсуждения |
|---|---|---|---|---|
| RH-QA-01 | Критический | Равенство `sigma−mirrorSigma=0` уже кодирует ключевую часть вывода о критической линии. | В комбинации с `sigma+mirrorSigma=1` оно непосредственно даёт `sigma=1/2`; API не выводит это равенство из функционального уравнения. | Решить, является ли это самостоятельной аксиомой RICIS или леммой, которую предстоит формализовать и доказать. |
| RH-QA-02 | Критический | `Type`, пространство типов, равенство типов и их инъективность не представлены в ядре. | Переход `Type(sigma)=Type(1−sigma) ⇒ sigma=1−sigma` невозможен без формальной инъективности. | Ввести типовой домен, `TypeOf`, `TypeEqual` и отдельную проверяемую аксиому/лемму `TypeInjective`. |
| RH-QA-03 | Критический | Нет правила, связывающего отражение `s↦1−s` с сохранением типа. | L0/L1 в текущем коде регулируют RICIS-выражения, но не определяют отражение комплексной точки и его типовое действие. | Ввести `Reflect`, аксиому симметрии нулей и явное правило сохранения либо преобразования типа. |
| RH-QA-04 | Высокий | Отсутствуют комплексная переменная, `zeta(s)`, `xi(s)` и отношение их нулей. | Нельзя выразить исходную аналитическую гипотезу как expression tree и проверить применимость предпосылок. | Спроектировать `RicisComplexExpression`, символические функции и ограниченный proof-контракт для нулей. |
| RH-QA-05 | Высокий | Нет квантора «для каждого нетривиального нуля». | Одна пара `sigma`, `mirrorSigma` не равна универсальному утверждению о множестве нулей. | Добавить отдельный кванторный/схемный уровень, не смешивая его с конечным `Prove` линейной системы. |
| RH-QA-06 | Средний | `RicisProofDocumentProfile` принимает текстовые аксиомы, но не проверяет их доказательства. | Это корректно для отчёта, но опасно, если читатель сочтёт список аксиом машинно верифицированным. | Сохранять статус `ConditionalTheorem` по умолчанию и в будущем связать профиль с идентификаторами проверяемых правил. |
| RH-QA-07 | Средний | Двухпеременный решатель проверяет совместимость координаты через конечные `double`, хотя для целочисленных систем результат уже печатается как точная дробь. | В экстремальных double-сценариях возможны отказ из-за overflow либо зависимость от двоичного представления нецелых констант. | Отдельно обсудить exact-rational backend для линейных систем с целыми/рациональными коэффициентами. |

## Подтверждённая безопасная теорема

Следующая формулировка полностью соответствует реализованному документному протоколу:

> **Условная теорема о типовой симметрии формальной пары.** При предпосылках `P1: sigma+mirrorSigma=1` и `P2: sigma−mirrorSigma=0` следует `sigma=1/2`; результат хранится как точное expression tree `Divide(1,2)`.

Эта теорема машинно воспроизводима, имеет промежуточные шаги `2·sigma=1`, `sigma=1/2`, подстановку и вывод `mirrorSigma=1/2`. Она не утверждает, что `P1` и `P2` верны для дзета-функции, и не содержит универсального квантора.

## Решение, ожидающее подтверждения автора

Для усиления именно Riemann-слоя необходимо определить, какой из двух путей является нормативным:

1. **Аксиоматический путь.** `TypeInjective` и сохранение типа при отражении принимаются как новые явно именованные аксиомы RICIS. Тогда результат получает корректный статус условной теоремы внутри расширенной системы, но внешний статус гипотезы Римана остаётся зависимым от применимости этих аксиом к `xi`/`zeta`.
2. **Доказательный путь.** Сначала реализуются комплексные объекты, отражение, типы и аналитические предпосылки; затем для каждого моста добавляется proof-rule с собственным проверяемым выводом. Только после этого можно обсуждать более сильный статус.

До такого решения библиотека не должна автоматически маркировать Riemann-связанный документ как «доказательство гипотезы Римана».
