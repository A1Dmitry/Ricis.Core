# QA-аудит академических доказательств RICIS III

## Цель и метод

Аудит проверяет соответствие между **фактически выполненным преобразованием expression tree** и академическим протоколом `StringBuilder`. Уравнения, ограничения и тезисы не компилируются при построении протокола; исполняются только производные деревья там, где это требуется для независимой регрессионной проверки.

| Идентификатор | Семейство | Инвариант | Первое наблюдение |
|---|---|---|---|
| P-QA-01 | SP2, разность квадратов | Если `AlgebraicReductionVisitor` сократил `(A²−B²)/(A+B)` до `A−B`, протокол должен показать факторизацию и сокращение. | Подтверждён разрыв детализации: есть только пара «до/после». |
| P-QA-02 | SP2, сумма кубов | Если полиномиальное деление вывело `(A³+B³)/(A+B)`, протокол должен показывать нормативную факторизацию суммы кубов. | Подтверждён разрыв детализации: есть только пара «до/после». |
| P-QA-03 | SP2, вложенная дробь | Если SP2 применил `F/(G/H) → (F·H)/G`, протокол должен фиксировать очищение вложенного знаменателя. | Подтверждён разрыв детализации для `x/(x/2) → 2`. |
| P-QA-04 | Система линейных уравнений | Константы, детерминант и обе выведенные координаты должны быть конечными `double`. | Подтверждено: система с `+∞` принимается и ошибочно выводит `x=∞`, `y=∞`. |
| P-QA-05 | Система линейных уравнений | Крайние конечные `double` не должны порождать ложный бесконечный результат из-за промежуточного overflow. | Подтверждено: `x+y=Max`, `x−y=Max` выводит `x=∞` в промежуточной формуле Крамера. |
| P-QA-06 | SP2, соседние факториалы | Распознанное `n!/(n−1)!` должно сокращаться независимо от представления единицы в expression tree. | Подтверждено: `BigInteger.One` представлен member-expression и не распознаётся как единица. |
| P-QA-07 | SP2, ассоциативные множители | Мультисетовое сокращение факторов не должно скрывать нормативный промежуточный шаг. | Подтверждено: `(a·a·a·a·a)/(a·a·a·a)` выводит `a`, но протокол не называет применённое сокращение. |

## Воспроизведённые результаты

| Сценарий | Фактический результат | Протокол / нарушение |
|---|---|---|
| `(x²−25)/(x+5)` | `x−5` | SP2 сработал, но детальная факторизация `(x+5)(x−5)/(x+5)` не записана. |
| `(x³+8)/(x+2)` | `x²−2x+4` | Полиномиальный SP2 сработал, но факторизация суммы кубов не записана. |
| `x/(x/2)` | `2` | Нормализация вложенной дроби сработала, но шаг `(x·2)/x` не записан. |
| `x+y=∞`, `x−y=1` | `x=∞`, `y=∞` | Метод принимает не конечный коэффициент и формирует ложное следствие. |
| `x+y=Max`, `x−y=Max` | Внутренняя формула даёт `x=∞` | Конечная система переполняет double-вычисление Крамера; корректное безопасное поведение — явное отклонение, а не доказательство `x=∞`. |
| `n!/(n−BigInteger.One)!` | Исходная дробь остаётся без SP2 | Правило факториалов ожидает `ConstantExpression(1)`, тогда как C# строит `MemberExpression(BigInteger.One)`. |
| `(a·a·a·a·a)/(a·a·a·a)` | `a` | SP2 срабатывает, но академический протокол выводит только обезличенное «до/после» без названия мультисетового сокращения. |

> Статус «подтверждён» означает, что стенд воспроизвёл дефект на текущем `HEAD ff72c0d`; это ещё не означает изменение аксиом RICIS III. Ремонт должен быть локальным: протокол расширяется только для реально распознанных схем, а невозможные `double`-системы явно отклоняются.
