# Академический протокол доказательства RICIS

## Назначение

`Prove` строит **символическое выведение** отложенного выражения RICIS и записывает его в переданный `StringBuilder`. Метод не исполняет условия, ограничения или тезис при построении. Он не является численным решателем, внешним верификатором истинности предпосылок либо механизмом пределов и правила Лопиталя.

```csharp
using System.Linq.Expressions;
using System.Text;
using Ricis.Core.Extensions;

Expression<Func<double, bool>>[] conditions =
[
    x => x >= -10.0,
];
Expression<Func<double, bool>>[] constraints =
[
    x => x != 5.0,
];
Expression<Func<double, double>> claim =
    x => ((x * x) - 25.0) / (x - 5.0);

var proof = new StringBuilder();
Expression<Func<double, double>> derived =
    conditions.Prove(constraints, claim, proof);
```

В примере `derived` получает нормализованное дерево `x => x + 5`, а `proof` — полный академический протокол предпосылок, ограничений и нормативных фаз.

## Контракт API

| Вход | Тип | Семантика |
|---|---|---|
| `conditions` | `IEnumerable<Expression<Func<T,bool>>>` | Формальные предпосылки; записываются в протокол и никогда не компилируются методом `Prove`. |
| `constraints` | `IEnumerable<Expression<Func<T,bool>>>` | Ограничения области; фиксируются отдельно от предпосылок. |
| `claim` | `Expression<Func<T,T>>`, `T : INumber<T>` | Доказываемая отложенная scalar-функция, проходящая обычный конвейер RICIS. |
| `proof` | `StringBuilder` | Выходной буфер. Существующее содержимое сохраняется, новый раздел дописывается. |
| Результат | `Expression<Func<T,T>>` | Независимое производное expression tree после нормализации RICIS. |

## Система двух линейных уравнений

Для строго определённого случая двух переменных доступен отдельный overload:

```csharp
IEnumerable<Expression<Func<double, double, bool>>> equations
    .Prove(constraints, claim, proof);
```

Он принимает **ровно два** уравнения форм `x+y=c`, `x−y=c`, `y+x=c` или `y−x=c`, а тезис — в форме `x=c` либо `y=c`. Правая часть и тезис должны быть конечными `double`-константами. Метод структурно читает коэффициенты из expression tree, отклоняет вырожденный детерминант, не-конечные константы, переполнение формулы Крамера и тезис, противоречащий полученному решению. В протокол заносятся четыре дерева: линейная комбинация с исключением переменной, выделение `x`, подстановка `x` в исходное уравнение и выделение `y`.

> Система не компилируется и не исполняется при построении доказательства. Данный overload намеренно не является универсальным решателем произвольных систем и не изменяет нормативные аксиомы RICIS III.

Полный контракт и пример `x+y=5`, `x−y=1` ⟹ `x=3` приведены в [RICIS_LINEAR_SYSTEM_PROOFS.md](RICIS_LINEAR_SYSTEM_PROOFS.md). Для интерактивного запуска используйте `dotnet run --project Ricis.Console/Ricis.Console.csproj -c Release -- --system-proof-demo`.

## Структура протокола

Метод дописывает разделы: **Предпосылки**, **Ограничения области**, **Тезис**, **Нормативный вывод** и **Заключение**. В вывод включаются только фазы, которые действительно изменили expression tree; для каждой такой фазы фиксируются нормативное основание, исходное и производное дерево. Неизменяющие и намеренно неприменённые фазы не засоряют академический текст.

| Фаза | Основание в протоколе |
|---|---|
| 0 | `ID-01 / L1: F/F → 1` |
| 0.5 | Полярные тождества `POL` |
| 1 | `SP2`: структурное сокращение до сингулярностей |
| 1.5 | O(1)-мосты `F·0 → 0_F`, `F/0 → ∞_F` |
| 2 | `A1/A4`: индексирование и отношение нулей |
| 5 | `Z-01/Z-02`, `A5/A6/A7` |

Для generic-домена, не допускающего double-domain root discovery, фаза A1/A4 не включается в текст, если она не изменила дерево. Это не ошибка и не численное приближение: конечная generic-алгебра остаётся в исходном типе `T`.

### Детализация SP2

Если результативная фаза SP2 распознана как одна из нормативных факторизаций, протокол не ограничивается начальным и конечным деревом. Он выводит реальные промежуточные `Expression`-деревья, каждый со своим основанием:

| Исходная форма | Промежуточные шаги |
|---|---|
| `(A²−B²)/(A−B)` | `((A−B)(A+B))/(A−B)` по разности квадратов; затем `A+B` по сокращению общего множителя. |
| `(A²−B²)/(A+B)` | `((A+B)(A−B))/(A+B)` по разности квадратов; затем `A−B` по сокращению общего множителя. |
| `(A³−B³)/(A−B)` | `((A−B)(A²+AB+B²))/(A−B)` по разности кубов; затем `A²+AB+B²` по сокращению. |
| `(A³+B³)/(A+B)` | `((A+B)(A²−AB+B²))/(A+B)` по сумме кубов; затем `A²−AB+B²` по сокращению. |
| `F/(G/H)` | `(F·H)/G` по очищению вложенного знаменателя; если последующее сокращение применено SP2, оно записывается отдельным шагом. |
| `(F₁·…·Fₙ)/(G₁·…·Gₘ)` | Оставшееся отношение после сокращения общего мультимножества встроенных факторов. |
| `n!/(n−1)!` | `n` по структурному сокращению соседних факториалов; распознаются как обычная константа единицы, так и `BigInteger.One`. |
| `(F·G)/F` или `(G·F)/F` | `G` как самостоятельный шаг SP2 сокращения общего множителя. |

Для иных результативных фаз протокол по-прежнему записывает проверяемую пару «до/после», не изобретая промежуточных преобразований, которых не произвёл RICIS-конвейер.

## Детерминированность и границы

> Протокол доказывает только последовательность применённых нормированных преобразований expression tree. Он не подменяет внешние математические аксиомы, не проверяет, что пользовательские условия истинны, и не вызывает входные делегаты.

Публичный `RicisPhasePipeline.SimplifyWithTrace` доступен, когда требуется получить полную структурированную трассировку, включая неизменяющие и намеренно пропущенные фазы, без форматирования текста. Для интерактивной демонстрации используйте:

```bash
dotnet run --project Ricis.Console/Ricis.Console.csproj -c Release -- --academic-proof-demo
```
