# Документный академический proof-отчёт RICIS

## Назначение

`ProveDocument` строит Markdown-документ по структуре академического доказательства: заголовок, аннотация, доказательный статус, определения, аксиомы и внешние предпосылки, тезис, машинно воспроизводимая трассировка, производное expression tree и явно перечисленные границы результата.

Метод **не повышает** доказательный статус исходного `Prove`. Он лишь делает его границы проверяемыми и видимыми в самом документе. Условия, ограничения и аксиомы записываются как предпосылки, но не компилируются, не исполняются и не признаются библиотекой истинными.

## API

```csharp
var profile = new RicisProofDocumentProfile(
    title: "Условная теорема",
    scope: RicisProofScope.ConditionalTheorem,
    @abstract: "Краткое описание результата.",
    theorem: "При P1 и P2 следует C.",
    definitions: ["Определение объекта X."],
    axioms: ["P1: ...", "P2: ..."],
    limitations: ["Истинность P1 и P2 не проверяется."]);

var document = new StringBuilder();
var derived = equations.ProveDocument(constraints, claim, profile, document);
```

Поддержаны оба существующих proof-контракта:

| Overload | Производное дерево |
|---|---|
| `IEnumerable<Expression<Func<T,bool>>>.ProveDocument(...)` | Нормализованная unary-функция `Expression<Func<T,T>>`. |
| `IEnumerable<Expression<Func<double,double,bool>>>.ProveDocument(...)` | Равенство координаты поддерживаемой двухпеременной линейной системы. |

## Доказательный статус

| Статус | Значение | Чего он не означает |
|---|---|---|
| `FiniteDerivation` | Воспроизводимое преобразование конкретных переданных expression tree. | Истинность общих аксиом, внешних данных или кванторного утверждения. |
| `ConditionalTheorem` | Заключение следует из явно перечисленных формальных предпосылок. | Что библиотека доказала сами предпосылки или любую более сильную внешнюю теорему. |

> Количество успешно пройденных тестов измеряет покрытие реализованных ветвей кода и устойчивость к известным регрессиям. Оно не является доказательством истинности внешней математической аксиомы, не проверяемой этими тестами.

## Структура сформированного документа

| Раздел | Содержимое |
|---|---|
| Аннотация | Заявленная цель документа. |
| Доказательный статус | Конечное выведение либо условная теорема. |
| Определения | Пользовательские определения, нужные для чтения предпосылок. |
| Аксиомы и внешние предпосылки | Явно названные элементы, истинность которых не проверяется API. |
| Теорема или конечный тезис | Формулировка цели. |
| Машинно воспроизводимое символическое выведение | Вложенный протокол действительных RICIS-шагов. |
| Воспроизводимый результат | Итоговое expression tree. |
| Границы и непроверенные утверждения | Исключённые из статуса доказательства заявления. |

Нормативные фазы и промежуточные SP2-деревья формируются существующим `Prove`; `ProveDocument` не создаёт вымышленных алгебраических шагов.

## Ограничения текущего ядра

Текущий документный слой способен точно документировать уже поддержанные scalar-выражения и две линейные координаты. Он пока не является proof assistant для комплексной аналитики: отсутствуют типы для комплексного `s`, символические узлы `ζ(s)` и `ξ(s)`, кванторы над нулями и verifier вывода внешних аналитических аксиом.

Поэтому Riemann-связанный сценарий должен оформляться как **условная конечная модель типовой симметрии**, пока указанные предпосылки не представлены и не проверяются отдельными правилами ядра.
