# Правила C#: форматирование строк, сообщения исключений и переносы

**Статус:** нормативное правило для новых и изменяемых C#-файлов RICIS.Core.  
**Цель:** исключить скрытые `System.FormatException` в диагностике и обеспечить предсказуемые переносы длинных сообщений для людей, тестов и агентных изменений.

## 1. Базовый принцип

Текст исключения является частью диагностического контракта. Он не должен создавать вторичную ошибку форматирования и скрывать исходную причину отказа.

> Если сообщение содержит generic type name, математические обозначения, формульные скобки или может быть изменено агентом, используйте **неформатирующую сборку строки**. Предпочтительный способ — `string.Concat` с одним логическим фрагментом на строку.

## 2. Разрешённые способы

| Сценарий | Предпочтительный способ | Причина |
|---|---|---|
| Короткое сообщение без `{` и `}` | Обычный string literal | Нет форматного риска |
| Два-три простых динамических значения | `$"...{value}..."` | Читаемо, если literal не содержит формульные braces |
| Сообщение с generic type name, формулой, `%`, `{`/`}`, TeX или RICIS-нотацией | `string.Concat(...)` | Не обращается к composite-format parser |
| Локализуемое форматное сообщение | `string.Format(CultureInfo.InvariantCulture, "...{0}...", value)` | Плейсхолдеры явны; literal braces экранированы `{{` и `}}` |
| Многострочный пользовательский текст | Raw string literal либо массив строк + `Environment.NewLine` | Переносы видимы и намеренны |

## 3. Запреты

1. Нельзя использовать `String.Format` или интерполированную строку, если фактически передаётся необработанный composite-format template с неэкранированными формульными `{` и `}`.
2. Нельзя строить сообщение с generic type name через неоднозначный template вида `"Type<{...}>"`, когда message может пройти через composite formatter.
3. Нельзя скрывать `FormatException` широким `catch`; исправляется источник форматирования.
4. Нельзя переносить строковый literal внутри слова или формулы только ради длины строки. Перенос допускается только между законченными смысловыми фрагментами.
5. Нельзя менять тип доменного исключения из-за ошибки сообщения. Валидация должна по-прежнему вернуть документированный `ArgumentException`, `ArgumentOutOfRangeException` или `NotSupportedException`.

## 4. Канонический безопасный перенос

Для длинного диагностического сообщения используется такой шаблон:

```csharp
throw new NotSupportedException(string.Concat(
    "CompoundInterest<", typeof(T).Name,
    "> не может точно представить процентную дробь r/100 для данной отложенной ставки. ",
    "Используйте decimal, double, Half, custom rational scalar либо целочисленную ставку, кратную 100%."));
```

Каждый перенос находится **между аргументами `string.Concat`**, а не внутри синтаксического элемента. Это сохраняет точное сообщение, не требует `{0}` и не может породить `FormatException` из-за содержимого literal.

## 5. Правило для форматных плейсхолдеров

Если `string.Format` действительно необходим, сразу после `{` должен идти ASCII digit, например `{0}`. Литеральные braces обязательно записываются как `{{` и `}}`.

```csharp
var message = string.Format(
    CultureInfo.InvariantCulture,
    "Expression {{x}} failed at position {0}.",
    position);
```

Следующая форма недопустима:

```csharp
// Недопустимо: `{x}` интерпретируется как неверный composite-format item.
var message = string.Format("Expression {x} failed.");
```

## 6. Требования к тестам

Каждое изменение validation message, где есть тип, формула или процентная дробь, должно иметь regression test, который:

1. проверяет документированный тип исключения;
2. проверяет минимум один стабильный смысловой фрагмент сообщения через `StringComparison.Ordinal`;
3. косвенно доказывает отсутствие `FormatException` — ожидаемый тип исключения успешно достигается;
4. не привязывается к полному тексту сообщения, если это не публичный API contract.

Пример:

```csharp
catch (NotSupportedException exception)
{
    Require(exception.Message.Contains("CompoundInterest<Int32>", StringComparison.Ordinal),
        "Диагностика должна указывать scalar-domain.");
    Require(exception.Message.Contains("r/100", StringComparison.Ordinal),
        "Диагностика должна объяснять непредставимую процентную дробь.");
}
```

## 7. Checklist для агента перед записью C#-кода

- [ ] Динамические значения в сообщении не проходят через неявный composite formatter.
- [ ] Все literal braces внутри `string.Format` экранированы.
- [ ] Длинная строка перенесена между аргументами, а не в середине формулы/слова.
- [ ] При необходимости message использует `string.Concat`.
- [ ] Regression test проверяет тип исключения и ключевой фрагмент сообщения.
- [ ] Никакой `FormatException` не подменяет доменную ошибку.

## 8. Применение к CompoundInterest

`EnsureRateIsRepresentable<T>` обязан отклонять `int`-ставку `5%` с `NotSupportedException`, поскольку `r/100` не представляется в integral scalar domain без усечения. Сообщение формируется через `string.Concat`, поэтому generic type name `CompoundInterest<Int32>` и формула `r/100` не могут стать ошибочным format template.
